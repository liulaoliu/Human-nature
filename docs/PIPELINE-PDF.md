# 链路一：杂志 PDF → 每篇文章的正文

目标：`public/articles.json`，形如

```json
{
  "009 Leaders - Interest-rate caps": {
    "title": "Interest-rate caps",
    "words": 689,
    "text": "A bad idea that is remarkably common THE Kenyan government has a problem. ..."
  }
}
```

键是**音频文件名去掉扩展名**——App 就是拿用户选的 mp3 的文件名来查这张表的。

整条链路的核心立场：**宁可一篇都不给，也不给一份看着能用、实际串篇的文本。**
所有设计都围绕这一条。

## 为什么这么难

Economist 的排版把「一篇文章」的边界弄得很不直观：

1. **同页多篇交错**。一页上甲在左栏开头、乙在左栏中段，而**甲的正文还要接到右栏**。
   所以「甲的内容在行流里不是连续的」。
2. **只有两个可靠的硬信号**：目录条目（起点）和文章末尾的花饰符（终点）。
   靠文字猜标题会错得离谱（后面「走过的弯路」写了为什么）。
3. **字体每期可能全变**。2016 用的是 `OfficinaSanITC-*` + `EcoNewtext-*` + `EcoPict-Two`；
   2021 换成 `MiloTE` / `MiloLNTE-Bold` / `ZapfDingbatsITCTT`，一个都不匹配。

## 定位正文的办法

### 起点

- 解析**目录页**，得到「标题 → 印刷页」。
  目录有两种写法，都要认：
  - 2016：`14 Interest-rate caps`（标题在前、页码在后，整行是标题字体）
  - 2021：`45 Joe Biden flies in`（页码在前、标题在后），**标题还会折行**，
    续行只有正文字体（`58 The return of the` + `mega-lbo`），漏了就会把标题截断
- 目录页的识别：**行数多**（真的目录页 70/36 行，正文页最多 10 行）。
  不能用「带页码的行占比」——正文里的「Also in this section」交叉引用框也带页码。
- 再用这个标题去正文里找**标题行**（按字体 + 字号），配合印刷页做校验。
  印刷页不是恒等于文档页号：PDF 里插了整页广告，2021 那期的偏移会从 0 跳到 2，
  所以要**从页眉读页码**建映射。

### 终点

**文章末尾有一个花饰符**，这是唯一精确的「本篇到此为止」信号：

- 2016：`EcoPict-Two`，渲染成 `7`，长这样：`... shoddy economics. 7`
- 2021：`ZapfDingbatsITCTT`，渲染成 `\x81`

页脚页码也用同一个字体，但**整行只有一个字符**，按词数排掉。

用终点而不是「下一篇标题在哪」：后者一遇到没定位到的文章，文字就被前一篇吞掉。

### 逐行定归属

因为一篇文章的内容在行流里不连续，不能简单地「起点到下一个起点」。逐行判断：

- 这一行**同栏里有某篇的终点标记** → 归「终点最靠前」的那篇（栏内按终点分界）
- 否则 → 归「起点最靠后」的那篇（栏内按起点分界）

### 起点要往上圈

定位到的常常是**大标题**那一行，而正文第一段压在标题**上面**（副题、栏目标签）。
所以定位完要往上走，把同栏、紧挨着的非正文行一起圈进来，但**撞到上一篇的结尾花饰就停**。

### 两代版式差异（2021 特有）

- **索引标题 ≠ 正文大标题**。索引写 `Boarded-up Portland`，正文大标题是
  `Plaid shirts and plywood`——两边对不上。
  但**音频标题等于标题上方的栏目标签（kicker，`EconSansOSMed` 11.6pt）**，
  所以音频标题直接去配 kicker。
- **音频标题是网络版标题**，和纸面索引也不完全一样（`Literacy` vs 索引 `Reading in America`），
  所以目录命中只有 26/74，剩下的走「音频标题直接配 kicker」。
- 页号靠 **mp3 编号和印刷顺序单调一致**来插值。
- 页眉在 y=33（2016 是 y<30），切页眉的高度也得按版式调。
- 每篇开头有个 31pt 的首字下沉、单独占一行。2016 那句「有大字就是摘引栏」的判据
  在这里会误伤，导致整篇词序被打乱——所以按版式关掉。

## 质量闸门（最重要的一条）

抽完算 **wpm = 词数 ÷ 音频时长 × 60**，只有落在 **110~175** 的才写进 JSON。

- 旁白朗读实测约 135 wpm（拿一篇已知正确的文章校准过：689 词 / 307 秒）
- 低于 110 = 正文被截断；高于 175 = 混进了别的文章

**不达标的不写、也不报错**，只在报告里列出来。理由是：串篇的文本比没有文本更糟——
用户会照着错的字念，而且看不出来。

抽取结束还会单独列「开头疑似半句话」的篇目（第一个词是小写，多半是起点定晚了）。
这类 wpm 拦不住——少一句照样是合理的语速。

实测：`009 Leaders - Interest-rate caps` 抽出来 **689/689 词，相似度 99.7%**
（唯一的差异是参照文本自身多了一个空格）。

### 换一期：先核对字体

```bash
py tools/inspect-fonts.py "<那期的pdf>"
```

列出全书字体清单（次数 / 字号 / 样文），并逐套对照 `PROFILES` 报告命中哪套。
一套都不命中就是新版式，照清单在 `tools/extract-articles.py` 的 `PROFILES` 里加一套：

```python
"2021": {
    "label": "2021-06-12（Milo + EconSans）",
    "title_font": "MiloLNTE-Bold",
    "title_size": (24.0, 40.0),          # 字号区间，同一字体常有好几种字号
    "anchor_fonts": (("MiloLNTE-Bold", 24.0, 40.0),
                     ("EconSansOSMed", 11.5, 11.7)),   # 能当起点的字体
    "deck_font": "EconSansOSMed",
    "deck_min": 11.0,
    "body_font": "MiloTE",
    "end_font": "ZapfDingbats",          # 结尾花饰
    "ad_fonts": ("Helvetica", ...),      # 广告字体，整行排掉
    "toc_numbered": True,               # 目录是「页码在前」那种写法
    "title_anchor": True,               # 目录对不上时，用音频标题直接配 kicker
    "pull_quote": False,                # 有没有「中间那栏放首段」的版式
    "drop_foreign_lines": True,         # 正文里非正文字体的行（地名等）要不要丢
    "top_skip": 45.0,                   # 页眉高度
}
```

### 生成时长表（闸门要用）

```bash
cd "<音频目录>" && for f in *.mp3; do
  printf '%s\t%s\n' "${f%.mp3}" "$(ffprobe -v error -show_entries format=duration -of csv=p=0 "$f")"
done > durations.tsv
```

### 抽取

```bash
py tools/extract-articles.py --profile=2016 \
   "<那期的pdf>" "<音频目录>" public/articles.json durations.tsv
```

- **可以一期一期攒**：默认合并进已有的库，不会覆盖上一期。同一篇重复跑以这次为准。
  要重建整库加 `--fresh`。
- 单独跑闸门：`py tools/validate-articles.py public/articles.json durations.tsv`
- 手上只有 PDF、没有音频时，也能单测抽取机器（不跑闸门）：
  `py tools/try-extract.py "<pdf>" <版式档案>`

## 抽不出来的时候会怎样

两种情况会**一篇都抽不出来**，这时脚本会打印
「本期一篇都没抽出来，库里原有的 N 篇原样保留」，原文库不动，App 退回手动粘：

- **字体名全变了**（改版）→ 起点定位 0 篇
- **PDF 是扫描件、没有文字层** → 字体清单是空的，整条路走不通

这是有意的：**失败要失败得安静且安全**，不能产出半对半错的数据。

## 走过的弯路（为什么现在这么做）

1. **按「标题行」猜文章边界**——试过，串篇严重：wpm 从 14 到 1210 都有，
   28 篇提取出 0 词。原因是边界一旦漏掉一篇，后面的文字全被前一篇吞掉。
   这就是为什么现在依赖**结尾花饰符**这个硬信号，并且加了 wpm 闸门。
2. **让用户手动粘原文**——中途退过这一步（见 `DESIGN.md` 记录 5），
   后来靠上面两个硬信号 + 闸门才敢自动化。
3. **目录页用「带页码的行占比」识别**——正文页的交叉引用框会被误判成目录页，
   42 页被判成目录。改成看行数。
4. **「有大字就是摘引栏」**——2016 成立（社论页中间那栏放首段），
   2021 每篇都有首字下沉，会把所有开篇栏都误判，整篇词序打乱。改成按版式开关。
5. **按期号兜底匹配音频**——删掉了。两期各自编期号，2016 有 `023`、2021 也有 `023`，
   指的是两篇不同的文章。就算只装一期，「023 随便什么标题」也会被配到库里那个 023 上。
   播着这期的音频、显示那篇文章，比没有文本更糟。
