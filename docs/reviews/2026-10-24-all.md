## 一、结论

这轮最该修的不是再加功能，而是**把「谁说了算」钉死**：路由里历史层由谁写、学习记录以服务端还是本机为准、词库版本号丢了以后还能不能写。功能本身已经完整，真正会让用户丢东西的是下面四类：

1. **浏览器返回键退不出文章**（P1）：`useArticleRoute` 的 ① 和 ③ 在同一次 commit 里互相抵消，按返回会重新 push 回文章。
2. **服务端学习记录水合后没有进入 React 状态**（P1）：本机已有记录时先画；服务端更新的记录只写回 localStorage，下一次编辑可能用旧数组覆盖服务端。
3. **词库读失败后仍允许强制覆盖**（P1）：`revision` 丢失后下一次 PUT 不带 `X-Vocab-Base`，服务端按“强制写”放行。
4. **静态服务不校验 Host**（P1）：DNS 重绑定可以拿到同源身份；dev 的 `/config.local.json` 还会把 API key 以 CORS 可读的方式暴露给其它 localhost 页面（P0）。

路由改造本身方向是对的：纯函数（`parseReaderRoute` / `path` 构造）和 `useRoutedFlows` 的 push/replace 语义已经建立。**问题在于“返回”只测了 rerender，没有真的移动 history**。先把这条补成真实历史测试，再谈拆文件。
