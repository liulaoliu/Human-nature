## 一、结论

这轮没有 P0，但有 **1 条 P1 安全缺口**，以及一条需要当成整体修的数据链：

1. **`/api/store/*` 的 GET 仍然绕开 Host 校验**：无 Origin 的同源 GET 被 `isSameOrigin()` 直接放行，而 `handleStoreApi()` 对 GET/HEAD 不调用守卫。DNS 重绑定页面可以把 `Host` 变成 `evil.com`，直接读 `/vocab`、`/learning`、`/export`，甚至 `/db` 整库。
2. **文章仓库有三处「本地镜像 vs 服务端」不一致**：启动 `reconcile()` 会把别的设备已删除的文章重新 PUT 回去；DELETE 失败时本地仍删，刷新后文章又回来；`get()` 不比较 `updatedAt`，备份导入可能以旧版为底。三处必须一起收口，不能只补一个 tombstone。
3. **外部输入守卫仍有缺口**：校准、手动改文、活动/练习/错题/类型统计仍直接 `JSON.parse(...) as T`，坏数据可以绕过 `normalizeLearning()` 进入 `sumCats()` 等业务函数。
4. **AI 跑批的生命周期不完整**：轮询每次返回全量结果、完成后的 run 只能等下一次跑批才回收、没有 job / 并发上限；金句课的两次 AI 请求还用了不会 abort 的临时 controller。
5. **口径重复仍在视图层**：`fresh`、月度标签、连续天数、打印行各有第二份实现；前后端学习记录 section 清单也没有契约测试钉住。

方向判断：**SQLite 迁移事务、备份前校验、词库版本冲突、路由纯函数和大部分 core 测试都不要动**。这轮该做的是「安全入口无条件收口 + 文章仓库状态机 + 外部输入守卫」，不是继续拆大文件。

## 四、重构路线

> 每一步都能单独构建、单独测试；不建议把下面几项塞进一个 commit。

### 阶段 1：安全入口收口（P1-1）

- `handleStoreApi()` 入口无条件校验 `Host` 是本机名；写请求再叠加 Origin / `Sec-Fetch-Site`。
- `/vocab`、`/learning`、`/export`、`/db` 的 GET 也走守卫；`/health` 可保留公开。
- 验收：本地 `curl http://127.0.0.1:<port>/api/store/vocab` 仍 200；`Host: evil.test` 的 GET/POST 全部 403；`/db` 不再被无 Origin 的恶意同源页拿到。

### 阶段 2：文章仓库状态机（P2-1 ～ P2-3）

- 定义唯一的 `pickNewer(server, local)` 与文章同步状态：`pendingUpload` / `pendingDelete` / `deletedAt` 三者选一套，不要同时存在多套。
- `reconcile()` 只上传 pending 新建/修改，不把镜像当新建；服务端 tombstone 优先于本地镜像。
- `remove()` 失败不落本地删除，返回失败或写墓碑；成功后清镜像。
- `get()` 复用 `pickNewer()`，和 `list()`/`reconcile()` 同口径。
- 验收：离线新建→恢复上传；离线修改→服务端不覆盖新内容；离线删除→恢复后不复活；B 设备删除→A 设备不复活；导入以较新版为底。

### 阶段 3：外部输入与导入事务（P2-4 ～ P2-6）

- 为校准/改文/活动/练习/错题/类型统计补 `core/` 守卫，返回好数据 + 丢弃条数；坏数据要提示，不能静默空库。
- 覆盖导入改为「先词库确认落盘，再文章/统计」，或引入暂存/回滚；错误文案区分解析失败与部分写入。
- 合并导入检查指纹 `writeRaw` 结果，失败时明确提示不要重复导入。
- 验收：`null`/字符串/数组/坏字段全部有测试；词库写失败文章不落盘或明确提示；配额失败不显示「合并完成」。

### 阶段 4：口径 SSOT 与测试契约（P2-7 ～ P2-11、P3-1 ～ P3-5）

- `fresh` / `hasReviewHistory` / `kindOf` 在视图层统一走 core，不再手写 `repetitions` 或 `kind ?? 'word'`。
- `StatsPanel` 月份标签从逻辑日取；`SideVocab` 目标行改用学习记录连续天数。
- 学习记录 section 加前后端契约测试；`assertLearning` 的数组键从同一名单派生。
- AI 分派器补表驱动测试；打印行从 `printPlan` 抽 helper。
- 验收：同一概念只有一份实现；新增 section/任务/handler 漏接线会被测试拦住。

### 阶段 5：AI 与 UI 工程债（P2-12 ～ P2-16、P3-6 ～ P3-9）

- AI 轮询加游标，完成态定时 GC，加 job/并发上限；金句课 AI 用可 abort 的 ref。
- 抽屉 Esc 走统一 hotkeys；`ModalShell` 统一弹层可访问性；卡片补键盘语义。
- 护眼主题颜色改 CSS 变量；TTS 预热失败退避重试；工具脚本避免拼 shell。
- 验收：取消/卸载后不再发请求；200 条结果轮询传输有界；键盘可完成弹层核心操作；护眼主题译文对比度达标。

## 五、人工验证

自动化覆盖不到、修完后要真机/真实服务确认的：

1. **DNS 重绑定**：用临时服务分别发 `Host: evil.test` + 无 Origin 的 GET（`/vocab`、`/learning`、`/export`、`/db`）和本地 Host 的同样请求；确认前者 403、后者 200。再用真实浏览器打开一个改 Host 的页面，确认读不到数据。
2. **文章离线链路**：停服务 → 新建/编辑/删除文章 → 重启服务 → 确认新建上传、编辑不回退、删除不复活；两台设备/两个浏览器配置删同一篇，确认不互相复活。
3. **导入半失败**：模拟 localStorage 配额满或词库 PUT 失败，覆盖导入一份备份；确认文章没有被静默写半套，提示与实际状态一致；恢复后重试同一份文件能收敛。
4. **坏 localStorage**：手工把 `shadowing.calibration.v1`、`shadowing.scripts.v1`、`reader:activity` 改成 `null`/`{}`/字符串，打开统计/校准/改文，确认不白屏且有丢弃提示。
5. **AI 跑批**：跑 100+ 条任务，观察轮询响应体是否随轮次线性增长；完成后 5–10 分钟再 GET，确认已回收；点取消/关闭金句课，确认服务端不再发新模型请求。
6. **键盘与主题**：只用键盘打开/关闭导出、今日计划、金句记录抽屉；确认 Esc 不连环退出、焦点回到触发按钮。切护眼主题看全文译文和「全部生词」来源列对比度。
7. **TTS 恢复**：断网/停 TTS 服务，选几句进入预热队列；恢复服务后不点新句子，确认队列自动继续。
