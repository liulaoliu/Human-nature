# 链路二：音频 → 分块 → 和原文对应

分两块：
- **切块**：纯音量分析，和刊物无关，任何音频都能用
- **和原文对应**：**近似**的，靠时长比例 + 至少一次手动校准

这一整条链路的定位是**导航**，不是字幕。

## 一、切块（`src/core/vad.ts`，40 行，没有 AI）

1. 每 10ms 算一次 RMS，转 dB
2. 出一条阈值线：`max(噪声底(p10) + 6dB, 中位数(p50) − 18dB)`
3. 线以上算有声音，连续的一段就是一个块
4. 间隔短于合并阈值（默认 400ms）的两块合并；短于 200ms 的丢掉

两个数取 `max` 是有意的：`p10 + 6` 防止阈值太低导致停顿永远切不出来；
`p50 − 18` 防止背景音乐把噪声底抬高后把轻声也一起切掉。

实测 Economist 音频（32kHz 单声道）：噪声底约 −52dB、语音约 −25dB，阈值自动落在 −43dB。
524 秒的文件切完 98ms，1858 秒的 Briefing 约 350ms。

界面上「切块」三档就是合并阈值：短 150ms / 中 400ms / 长 700ms。
默认「中」在 Economist 上约 5.4 秒一块（约 14 个词，接近一句）。

### 为什么不做音频切片

不导出逐句 mp3：那样要重新编码，格式不可控。
逐块播放用 `<audio>` + `currentTime` 区间就够了，零成本，也不占额外存储。

### 也没有文本文件可用

Economist 的音频包里**一个文本文件都没有**（zip 里只有 mp3/mp4）。
所以「切块」这一步完全不依赖文本——文本是另一条链路单独拿到的
（见 [`PIPELINE-PDF.md`](PIPELINE-PDF.md)）。

## 二、和原文对应（近似）

### 基本做法

按 **块时长比例** 把词摊开：第 i 块分到
`[已过时长/总时长 × 总词数, 下一块同理)` 这个区间的词，再把内部切点往句末挪。

不做强制对齐（forced alignment）的理由：135 wpm 的朗读语速相当稳定，
比例摊出来的误差在「导航」这个精度下够用；而强对齐要么得跑 ASR 模型
（要 wasm 运行时，包体积翻几倍），要么得人工校时间轴。

### 句末吸附

内部切点会往最近的句末挪，挪的时候躲三个坑：

1. **下一句不是大写开头**就不算句末——`The U.S. economy` 不会被切成两半
2. **括号没闭合**就不算——`(see page 4. Note this).` 不会切在括号里
3. **搜索窗口按块自身大小算（±60%）**——固定窗口会把 6 词的小块撑成 16 词，比例就废了

实测 `009`（307 秒 / 689 词）：切成 46 块，每块中位 15 词，**80% 的块收在句末**。
剩下 20% 是 1.4 秒的短块——要把切点挪到句末就得吃掉下一块的词，不挪反而更准。

### 唯一的硬保证

> **所有块按顺序拼起来 == 原文的词序，一个词不丢、不重、不乱序。**

这条有测试守着，而且**手动校准之后也守**。定位是导航，所以只承诺这一件事。

## 三、误差从哪来，怎么校准

有两种来源，**要分开治**。

### ① 音频里有文本中没有的内容（固定偏移）

最常见的是**正文前面那段开场白**（播报员介绍本期内容之类）。
实测 `012 Briefing - The post-truth world`：正文第一句
`Dishonesty in politics is nothing new;` 出现在**第 4 块**，前面 3 块文本里没有。

已确认不是抽取抽漏了——那一篇在 PDF 里确实就从这句开始（前面只有副题），
而且 4188 词 ÷ 1858 秒 = 135 wpm，和已知正确的那篇一致。

**症状**：高亮整体落在听到的后面，误差**是个固定词数**，不会自己收敛。

**办法**：听到正文第一句时切到那一块，按 **`S`**（或点「正文从这块开始」）。
之后词就从这一块开始摊，前面的块留空并注明原因。

两个好处：误差一次清掉；而且摊词的区间变成了**真实的朗读区间**，
后面的漂移跟着变小。

### ② 音频没把文本里的每个词都念出来（仍是固定偏移）

副题（standfirst）通常不念，有些段落也可能略过。

**办法**：`[` / `]` 微调（或点 ±3 / ±15），把词窗整体平移。

- 高亮**落后**于听到的 → 往 `+`（把文字往前赶）
- 高亮**跑在**听到的前面 → 往 `−`（把文字往后挪）

**实现上怎么保证不丢词**：平移量加在各块边界上，再夹到 `[0, 总词数]`；
首尾锚死在 0 和总词数，被挤出去的词归给第一块/最后一块。
所以「拼起来等于原文」这条硬保证不受影响，测试里对 ±1/±7/±30/±999 都验过。

### ③ 越往后差得越多（累积漂移）——**目前修不掉**

如果开头是对得上的，中间某处开始差出一整句，那是比例映射本身的漂移
（块与块之间的停顿比例不一致，累积起来）。
上面两个办法都治不了，需要「重锚」：在任意一块上重新对一次，后面重新摊。

## 四、连续跟读（可选）

勾上之后空格跑完整一圈，一圈只按一次：

```
标准音 →（空档 0.6 秒）→ 录音 → 说完停 1.6 秒自动结束 → 回放我的录音
```

**为什么不用「固定录音时长」**：算过，5.4 秒的块给 10.6 秒——
正常速度读完还剩 5 秒**干等空白**，而且读得慢的人还是会被掐掉。两头不讨好。

**改成看麦克风电平**：说话声过阈值就记着，连续静音超过 **1.6 秒**算读完。

| 参数 | 值 | 为什么 |
|---|---|---|
| 说话判定阈值 | 峰值 `0.06` | 室内底噪一般低于 0.02，说话峰值远高于 0.1 |
| 静音多久算读完 | `1.6 秒` | 句中停顿不到 1 秒；跟读时想一下再开口可能超过 1 秒，所以取宽一点 |
| 兜底上限 | `块长 × 2 + 3 秒`（下限 4 秒，上限 90 秒） | 麦没声/底噪太高导致判定失灵时，不会无限录下去 |

**判定失灵最坏的结果只是「等满兜底时长」**，不会丢录音、也不会卡住。

空档 0.6 秒是给换气、把嘴张开用的——不留的话录音开头永远是你的吸气声。

手动那条路完全没动：`R` 只管录音，不勾这个选项时空格还是播放/暂停。

### 已知不足

- 判定阈值 `0.06` / `1.6 秒` 是**估的**，只有真麦克风能校准。
  如果发现句中偶尔被提前掐掉，就是 1.6 太小。
- **录音首尾的静音没裁**：回放时会把开头那 0.6 秒空档和结尾 1.6 秒静音一起放出来。
  `Take` 上加 `speechFrom` / `speechTo`、`playTake` 支持区间播放就能去掉。
  记在 `TODO.md` 里。

## 五、播放器那边踩过的坑

- **不用 `timeupdate` 判边界**：它约 250ms 触发一次，逐块播放会明显跑过头
  （吃掉下一个字）。改用 `requestAnimationFrame` 轮询 `currentTime`，终点提前 20ms。
- **暂停要「接着播」**：靠 `AudioPlayerPort.position`（就是 `currentTime`）记住停在哪。
  但**换了块就必须作废这个位置**——第 1 块停在 1.5 秒，切到区间是 `[1.09, 1.70]` 的第 2 块
  会从那 1.5 秒开始播，等于跳掉小半块。
- **整篇连播 / A/B 对比会自己移动播放位置**，也会作废暂停点。
- 快速连按「下一块」不会叠音：`playRange` 一进来就 `pause()`，
  会取消上一块的 `requestAnimationFrame` 并把旧 Promise resolve 掉。
