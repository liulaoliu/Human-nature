# Economist 精读与复读工具 — 项目开发大纲

**版本**：2.0
**技术栈**：React + TypeScript + Vite + Vitest（复用现有 shadowing 仓库）
**开发模式**：TDD（测试驱动开发）
**核心约束**：文本中间层格式必须无缝对接已有音频复读模块

---

## 0. 文档用途与 v2 修订说明

本文档是项目的开发大纲，包含架构、数据模型、模块职责、TDD 流程、技术选型和接口约定。目标是让开发者（或 AI 编码助手）能按本文档直接开工。

v2 相对 v1 的修订（依据两期 PDF 的实测结果和需求讨论）：

| 主题 | v1 | v2 |
|---|---|---|
| 文本来源 | 人工复制为主 | **PyMuPDF 抽取为主**，人工复制 / OCR 兜底 |
| 清洗 | 假设输入干净，只做三件事 | 按真实 PDF 伪影清洗（软连字符 / ligature / 粘连 / 截断） |
| 精读产出 | 调 DeepSeek API 批量分析 | **一键生成提示词 → 复制到网页版 DeepSeek → 粘回解析**；API 可选 |
| 生词 | `Sentence.vocab: string[]` | 新增一等公民 **`VocabItem` + `VocabLibrary`**（音标/含义/用法/例句/状态） |
| 输出 | JSON / Anki CSV | 新增 **A4 打印**；Anki CSV 保留 |
| 排期 | `ReviewState`（自研 SRS） | **自研 SRS 与 Anki 并存**（两套都要） |
| 句子级音频 | 外部强制对齐 | **复用 `alignText.ts` 做近似投影**，`audio` 允许 `null` |
| 页码/结构 | 通用 `src/core/*` | 目录结构贴合现有仓库（`src/core`、`src/state`、`src/adapters`、`src/ui`） |

> 版权：素材（PDF、音频）和抽取产物 `public/articles.json` 都不进仓库，本地生成。仅供个人学习。

## 1. 项目目标

把《经济学人》digital PDF 的文本，变成**可舒服阅读、可划词标生词、可查询、可打印、可复读**的学习材料，并集成进现有跟读 App。

具体要解决的四件事：

1. **读**：从 PDF 抽出干净正文，在网页里舒服地读。
2. **标**：边读边快速标记生词（划词即标、按 lemma 去重、跨文章累积）。
3. **查**：选中文字，一键生成"原文 + 提示词"，复制到网页版 DeepSeek，再把结果粘回成结构化词条。
4. **用**：
   - **A4 打印**纸质版（单词 / 音标 / 含义 / 用法 / 例句）；
   - **Anki CSV** 导出（排期交给 Anki）；
   - App 内自研复习排期（`ReviewState`）；
   - 干净正文喂给**现有音频复读模块**（`articles.json` 兼容，App 零改动）。

核心约束：

- 文本中间层格式必须无缝对接已有音频复读模块。
- 采用 TDD。
- 技术栈：React + TypeScript。
- 文本保存要可靠，支持导出和外部消费。

## 2. 总体架构

    [输入层]
      A. PyMuPDF 抽取（主路径）：PDF → 清洗 → 段落文本
      B. 人工复制（兜底）
      C. 截图 → OCR（最低优先）
            │
            ▼
    [清洗层]  原始文本 → 规范文本（每段一行、段间空行）
      1. ligature 归一（ﬁ→fi、ﬀ→ff…）
      2. 软连字符处理（U+00AD）
      3. 行末连字符断词修复
      4. 合并行内硬换行
      5. 按空行切段落
            │
            ▼
    [切分层]  规范文本 → Paragraph / Sentence 列表（id 稳定）
            │
            ▼
    [中间层]  统一 JSON 文档模型 + 词库（核心资产）
            │
      ┌─────┼───────────────┐
      ▼     ▼               ▼
   [精读]  [复读]         [生词]
   提示词  句子-音频        词库 VocabItem
   粘贴    近似投影        查询/导出/打印
   解析    时间轴写回       App 内 SRS + Anki
      └─────┬───────────────┘
            ▼
    [学习层]  React 网页界面
      原文/翻译/语法/搭配/生词
      划词标记 + 一键提示词 + 词库
      音频播放器 + 逐句联动
            │
            ▼
    [导出层]  A4 打印 / Anki CSV / 标准 JSON / articles.json（喂音频模块）

关键原则：中间层 JSON 和词库是唯一真相来源，其余都只读写它们，不各自维护状态。

## 3. 中间层数据模型

`src/types/document.ts`。字段全部可序列化（不含函数/Map/Set），时间统一用秒、保留两位小数，ISO 8601 时间戳用字符串。

### 3.1 DocumentMeta

- `id`：唯一标识，建议 `issue + slug`
- `title`：文章标题
- `issue`：期号，如 `"2026-09-27"`
- `section`：栏目，如 `"Leaders"`
- `sourceFormat`：`pdf_extract` | `manual_copy` | `screenshot_ocr`
- `audioFile`：音频文件名（喂音频模块的桥），未对齐时 `null`
- `createdAt` / `updatedAt`：ISO 8601 字符串

### 3.2 AudioSegment

- `start` / `end`：秒，保留两位小数。
- 由 `alignText.ts` 的块级比例 + 手动锚点**近似投影**得到，不是强制对齐。
- `null` 表示未对齐，播放器必须降级为纯文本模式。

### 3.3 ReviewState（自研排期）

- `ease`：难度系数，初始 2.5
- `due`：下次复习时间，ISO 8601，未排期时 `null`
- `interval`：间隔天数
- `repetitions`：已复习次数

> 与 Anki 并存：Anki 负责每日刷卡，本字段负责 App 内自己的排期与筛选。

### 3.4 Sentence

- `id`：如 `"s001"`
- `paraId`：所属段落，如 `"p01"`
- `text`：原文，已清理
- `audio`：`AudioSegment | null`
- `translation`：中文翻译，`null` 表示未查
- `grammarNote`：长难句结构说明，`null` 表示无
- `collocations`：写作搭配列表
- `vocab`：本句出现的生词（词形）
- `tags`：如 `["long_sentence"]`
- `reviewState`

### 3.5 Paragraph

- `id`：如 `"p01"`
- `sentenceIds`：按顺序

### 3.6 VocabItem（生词，学习层核心）

v1 只有词形，v2 升级为完整词条：

- `id`：唯一标识
- `word`：原词形
- `lemma`：归一化形式（`running` / `ran` → `run`），去重用
- `phonetic`：音标
- `partOfSpeech`：词性
- `meaning`：中文含义
- `usage`：用法 / 搭配（字符串列表，v1 的 collocations 并入这里）
- `examples`：例句列表 `{ text, translation?, articleId?, fileName?, sentenceId? }`
- `source`：来源 `{ articleId, fileName, sentenceId, sentenceText }`
- `status`：`unqueried` | `queried` | `edited` | `mastered`
- `note`：个人笔记
- `tags`：标签
- `reviewState`
- `createdAt` / `updatedAt`

### 3.7 VocabLibrary

- `schemaVersion`
- `items`：`VocabItem[]`，跨文章累积，按 lemma 去重。

### 3.8 AnalysisResult（提示词/粘贴/API 共用）

一键提示词的"粘回解析"和（以后可选的）API 共用同一结构：

- `sentences`：`{ sentenceId, translation?, grammarNote?, collocations?, vocab? }[]`
- `words`：`{ word, phonetic?, partOfSpeech?, meaning?, usage?, examples? }[]`

### 3.9 EconomistDocument

- `schemaVersion`
- `meta`
- `paragraphs`
- `sentences`

### 3.10 约束

- `sentences[]` 是精读和复读的共同最小单元。
- `audio === null` 表示未对齐，复读模块必须能处理。
- 所有字段可序列化，`JSON.stringify` 无损。
- 加 `schemaVersion`，任何破坏性改动都要写迁移。

## 4. 模块拆解

### 4.1 清洗模块（`src/core/cleaner.ts`）

职责：把任意来源的原始文本，清成"每段一行、段间空行"的规范文本。**v2 必须处理真实 PDF 伪影。**

实测两期的伪影正好相反，都要覆盖：

| 伪影 | 2021-06-12 | 2016-09-10 |
|---|---|---|
| 软连字符 U+00AD | 2807 个 | 0 |
| 行末连字符 + 换行 | 31 个 | 2048 个 |
| ligature（ﬁ/ﬀ…） | 1105 个 | 1042 个 |
| 词内莫名空格 | 多（`af fordable`、`Mississip pi's`） | 少 |
| 词粘连（`MrTrump`、`emergingeconomies`） | 少 | 多 |

规则：

1. **ligature 归一**：`\ufb00-\ufb06` → `ff/fi/fl/ffi/ffl/ft/st`。
2. **软连字符 U+00AD**：删除并直接接合（`sounding\u00adout` → `soundingout`）。
   注意：若软连字符实为实义连字符（`shake\u00adup`），会丢连字符；由人工通读修正，或后续用词典兜。
3. **行末连字符断词**：`com-\npared` → `compared`；用小词典判断，`co-\nfounder` 若 `cofounder` 不在词典则保留连字符。词典可先精简，后替换。
4. **合并行内硬换行**：上一行末尾不是句末标点（`. ? ! " ”`）且本行首字母小写 → 合并。
5. **按空行切段落**：每段一行，段间空行。

**不处理**（留给人工或 Python 端）：词粘连（`MrTrump`）、分栏串栏。词粘连最好在 PyMuPDF 抽取端用词框间距修，TS 端不猜。

接口契约：

- 输入：原始文本字符串
- 输出：清理后的规范文本字符串

### 4.2 切分模块（`src/core/segmenter.ts`）

职责：把规范段落文本切成 `Paragraph` + `Sentence`。

规则：

- 按空行切段落，`p01` 递增。
- 每段按句末标点（`. ? !` 及弯引号 `”`）切句，`s001` 递增。
- 优先用浏览器原生 `Intl.Segmenter(..., { granularity: 'sentence' })` 做第一层，再用缩写白名单（`Mr.`、`U.S.`、`e.g.`、`i.e.`）修补，避免在正则上堆特例。
- id 稳定：顺序 id + 原句文本，便于缓存与对齐。

### 4.3 精读模块（`src/core/analyzer.ts`）

职责：**生成提示词 + 解析粘回结果**（不默认直连 API）。

提示词生成：

- 输入：选中文本（词/句/段）+ 任务类型（`translate` | `lookup` | `grammar` | `collocations` | `extract_vocab` | `summarize`）。
- 输出：一段可直接粘贴到网页版 DeepSeek 的提示词（角色 + 任务 + 输出格式 + 定界原文）。
- 输出格式要稳定、可解析，例如查词：

      word | phonetic | pos | meaning | usage | example
      一行一个单词

- 提供"复制到剪贴板"。

粘贴解析：

- 输入：DeepSeek 返回的文本。
- 输出：`AnalysisResult`。
- 能解析 → 填进对应 `Sentence` / `VocabItem`；不能解析 → 原样存为该词/句的 `note`，不丢。

批处理：允许选中整篇/整段，一次生成"提取生词 + 查词"的大提示词，返回一张表，一次粘回填多个词条。

可选 API：同一 `AnalysisResult` 结构，接 DeepSeek API 时不改数据模型。默认不做（避免浏览器暴露密钥）。

缓存：以句子/单词文本 hash 为 key，缓存解析结果，key 里要带提示词版本。

### 4.4 音频对齐模块（`src/core/aligner.ts`）

职责：把句子与音频时间轴对应，写回 `Sentence.audio`。

**v2 明确：不做强制对齐。** 复用现有 `src/core/alignText.ts` 的"块级比例摊词 + 手动锚点"，把块时间**近似投影**到句子：

- 句子落在某块内 → 按词在块内的比例分配时间；
- 跨块句子 → 合并覆盖的块区间；
- 对齐失败/低置信 → `audio` 保持 `null`。

约束：

- 时间单位秒、两位小数。
- `audio === null` 的句子，播放器必须能处理。
- 写回不改变其他字段，保证往返无损。

### 4.5 词库模块（`src/core/vocab.ts` + `src/adapters/vocabRepo.ts`）

职责：生词的增删查改、去重、持久化。

- 按 `lemma` 去重：同一词形归一条，`word` 记录首次词形。
- 标记时自动回填 `source`（哪篇、哪句、文件名）。
- 跨文章累积，独立于任何单篇文档。
- 持久化：**IndexedDB**（词条带释义/例句，localStorage 会爆），加 `schemaVersion` + 迁移。
- 支持：手动编辑、按文章/日期/字母分组、`status` 流转。

### 4.6 存储模块（`src/core/storage.ts` + adapters）

职责：文档与词库的持久化、导入、导出。

接口契约：

- `save` / `load` / `list` / `remove`
- `exportJSON` / `importJSON`
- `exportAnkiCSV`：两列（正面 `word + phonetic`，反面 `meaning + usage + examples`），带 `tags`（文章、日期）。
- `exportPrintHTML`：A4 打印视图（`@media print`，两栏）。

导出格式：标准 JSON，就是 `EconomistDocument` / `VocabLibrary`，不做额外包装。

### 4.7 网页界面（`src/ui/`）

复用现有 App，新增"精读"相关组件。

| 组件 | 职责 |
|---|---|
| ArticleList | 文章列表，选择/删除/导入 |
| ReaderView | 主阅读界面，段落 + 句子渲染 |
| SentenceCard | 单句：原文、翻译、语法、搭配、生词 |
| VocabPanel | 选中词 → 标记；一键提示词按钮组；粘贴结果 |
| VocabLibraryView | 词库浏览/编辑/筛选 |
| PrintView | A4 打印排版 |
| ExportPanel | 导出 JSON / Anki CSV / 打印 |
| AudioPlayer | 复用现有播放器，逐句联动，`audio === null` 降级 |

交互约定：

- 点击句子 → 音频跳到 `audio.start`（近似）。
- 播放到 `audio.end` → 自动暂停或跳下一句（可配置）。
- `audio === null` → 点击不跳转，只高亮。
- 划选文字 → 出现任务按钮（翻译/查词/语法/搭配/提取生词/概述）→ 生成提示词并复制。
- 粘回结果 → 解析成词条/翻译，失败则存笔记。

## 5. TDD 开发流程

核心原则：先写测试，再写实现。每个模块都必须有对应测试文件。

### 5.1 测试框架

- Vitest（已配置，`environment: node`）
- Testing Library（React 组件测试，后续需要时加）
- 网络：优先不依赖真实 API；提示词/解析是纯函数，直接测。若接 API，再用 MSW mock。

### 5.2 各模块测试要求

清洗模块：

- ligature 归一。
- 软连字符删除与接合。
- 行末连字符断词（词典命中/未命中）。
- 行内硬换行合并；句末标点不合并。
- 空行切段落。
- 边界：空输入、只有空行、只有一行、末尾无换行。
- 真实脏样本回归（取自 `articles.json`）。

切分模块：

- 基本句切分；缩写不误切。
- 段落/句子 id 生成与顺序。

精读模块：

- 每种任务的提示词包含原文与输出格式。
- 粘回解析：合法表 → `AnalysisResult`；非法 → 存笔记。
- 缓存命中不发请求。

词库模块：

- 按 lemma 去重；`source` 回填。
- 增删查改往返一致。

存储模块：

- save → load、export → import 往返一致。
- Anki CSV 列与转义正确。
- schemaVersion 迁移。

音频对齐：

- 投影正确写回；未对齐保持 `null`。
- 无效 sentenceId 被忽略或报错。

界面组件：

- SentenceCard 渲染。
- AudioPlayer 在 `audio === null` 时禁用跳转。
- VocabPanel 提示词生成与复制。

### 5.3 TDD 循环

1. 红：写一个失败的测试，描述期望行为。
2. 绿：写最简实现让测试通过。
3. 重构：在测试保护下优化代码。

## 6. 技术选型

| 环节 | 选型 | 理由 |
|---|---|---|
| 语言 | TypeScript | 类型安全，中间层模型需严格约束 |
| 框架 | React | 项目要求 |
| 构建 | Vite | 快，与 Vitest 集成好 |
| 测试 | Vitest + Testing Library | 与 Vite 生态一致 |
| PDF 抽取 | Python + PyMuPDF | 快、能拿字体/坐标，已有 `tools/extract-articles.py` |
| LLM | 网页版 DeepSeek（提示词+粘回） | 无密钥、无跨域、不花钱；API 可选 |
| 存储 | IndexedDB（文档/词库）+ localStorage（小配置） | 词条带释义，localStorage 会爆 |
| 状态管理 | React Context + useReducer | 规模不大，不需要 Redux |
| 样式 | 复用 `src/ui/styles.css` | 与现有 App 一致 |
| 音频 | HTML5 Audio API（现有） | 原生，够用 |
| Anki | CSV 导出 | 不自己生成 `.apkg`（浏览器里太重） |

## 8. 开发路线

### Phase 1 — 核心管线跑通

1. 定义中间层数据模型（`types/document.ts`）。

## 9. 接口约定（供外部音频模块消费）

输入：`EconomistDocument` 的 JSON。

音频模块需要读的字段：

- `meta.audioFile`
- `sentences[].id`
- `sentences[].text`
- `sentences[].audio.start / end`（可能为 `null`）

音频模块需要写的字段：

- `sentences[].audio`：对齐后的 `{ start, end }`

约束：

- 时间单位秒、两位小数。
- `audio === null` 表示未对齐，播放器必须能处理。
- 写回后不改其他字段，保证往返无损。

**兼容现有 App**：继续生成 `articles.json` 兼容格式（键 = 音频文件名去扩展名，值 = `{ title, words, text }`），现有 App 零改动。

## 10. 风险与注意事项

- **PDF 抽取质量**：两期各约 46% 的音频没有文本；2021 的软连字符和 2016 的词粘连是主要脏点。先修抽取，再谈其他。
- 提示词返回的稳定性：明确输出格式，解析失败降级存笔记。
- 词粘连：TS 端不猜，交给 PyMuPDF 抽取端按词框间距处理。
- 音频对齐：近似投影，低置信度保持 `null`，不强行写时间戳。
- 存储：词条带释义会撑爆 localStorage，直接上 IndexedDB。
- 版权：仅供个人学习，不公开分发解析后的全文或音频；`public/articles.json` 与素材不进仓库。
- 不要过度设计：第一版目标是"一篇文章从 PDF 到打印"跑通，再按使用结果优化。功能可以多，但每一步都要有测试。
